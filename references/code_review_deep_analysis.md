## 一、功能全景

Warp Code Review 是一个**内置于终端的代码审查面板**，允许用户在不离开终端的情况下查看 git diff、编写行内评论、执行 Git 操作（commit/push/create PR），并与 AI 深度集成。

### 1.1 核心能力矩阵

| 能力 | 说明 |
|------|------|
| Diff 查看 | 支持 HEAD / MainBranch / OtherBranch 三种比较模式 |
| 行内评论 | Native + GitHub PR 导入双来源，支持行级/文件级/通用评论 |
| Git 操作 | Commit → Push → Create PR 完整工作流（含链式操作） |
| AI 集成 | 自动生成 commit message、PR title、PR description |
| Diff 上下文 | 将 diff 作为 AI Agent 的上下文附件 |
| 查找替换 | 面板内搜索功能 |

### 1.2 入口方式

Code Review 面板可通过以下入口打开（`CodeReviewPaneEntrypoint` 枚举）：

| 入口 | 触发方式 |
|------|----------|
| `GitDiffChip` | 点击 Git Diff 上下文芯片 |
| `AgentModeCompleted` | Agent 模式完成后自动打开 |
| `AgentModeRunning` | Agent 运行中 |
| `SlashCommand` | `/code-review` 命令 |
| `InvokedByAgent` | Agent 调用 |
| `ForceOpened` | 强制打开 |
| `CodeDiffHeader` | 代码 diff 头部 |
| `PaneHeader` | 面板头部按钮 |
| `RightPanel` | 右侧面板 |
| `CLIAgentView` | CLI Agent 视图 |

#### APP-3918: Git Operations Button in Code Review Header

**目的：** 在 Code Review 面板头部添加上下文感知的分割按钮（split button），根据仓库状态自动展示最相关的 Git 操作。

**关键行为：**

- 分割按钮 = "主操作按钮" + "折叠箭头"
- 五种 `PrimaryGitActionMode`：

| 模式 | 触发条件 |
|------|----------|
| Commit | 有未提交变更 |
| Publish | 无上游但有本地提交 |
| Push | 有上游且有未推送提交 |
| View PR | 已有 PR |
| Create PR | 一切已推送、无 PR、非主分支 |
| Disabled Commit | 主分支无变更（兜底） |

- 折叠箭头在 Commit/Push 模式下可见，其他模式隐藏
- 按钮状态随 diff stats 和 unpushed-commits 变化自动刷新

**技术决策：**

- 新增 `PrimaryGitActionMode` 私有枚举
- `DiffMetadata` 新增 `has_upstream: bool` 字段
- 头部渲染通过 `CodeReviewHeaderFields` 传递按钮组件
- 功能由 `FeatureFlag::GitOperationsInCodeReview` 控制

**依赖：** APP-3632（头部 UI 重构）。是后续 APP-3919/3920/3922 的父分支。

---

#### APP-3919: Commit Dialog

**目的：** 模态覆盖层，在 diff 视图中编写和执行 git commit。

**关键行为：**

- 居中模态覆盖层，四个区域：分支（只读）、变更（可折叠文件列表 + 含/不含未暂存开关）、提交消息编辑器、意图选择器
- 支持 ESC / Cancel / X 关闭
- 成功后 toast + 刷新 diffs + metadata + PR info
- 失败后关闭对话框 + 错误 toast
- 编辑器自动聚焦，支持软换行和自动增长

**技术决策：**

- 新文件 `commit_dialog.rs`（约 718 行）
- `CommitIntent` 枚举：`CommitOnly`（预留 `CommitAndPush` / `CommitAndCreatePr`）
- `get_file_change_entries` 异步函数获取文件变更统计
- `CodeReviewView` 新增 `commit_dialog: Option<ViewHandle<CommitDialog>>`

**依赖：** APP-3918。

#### APP-3920: Push and Publish Dialogs

**目的：** Push/Publish 确认对话框 + **将 CommitDialog 和 PushDialog 统一为 GitDialog**。

> **这是整个栈最关键的架构转折点。**

**关键行为：**

- 460px 宽居中模态，含分支信息、可滚动提交列表（最大 300px）、每提交可展开查看文件级统计
- "Commit and push"：commit 成功后自动链式执行 push
- Publish = 首次推送（设置上游），与 push 使用同一 `run_push`（始终带 `--set-upstream`）

**技术决策（重大重构）：**

```
之前:  CommitDialog (独立) + PushDialog (独立)
之后:  GitDialog { mode: Commit | Push }
       ├── mod.rs    → 共享 chrome + 生命周期
       ├── commit.rs → 独立状态和渲染
       └── push.rs   → 独立状态和渲染
```

- `GitDialogMode` 枚举
- 统一事件模型：`Completed / Cancelled`
- `CodeReviewView` 合并为单一 `git_dialog: Option<ViewHandle<GitDialog>>`

**依赖：** APP-3918 + APP-3919。为 APP-3922（PR 对话框）铺路。

#### APP-3922: Create PR Dialog

**目的：** "Create PR" 对话框和 "Commit and create PR" 链式操作。

**关键行为：**

- 显示分支名 + 聚合变更统计 + 可展开逐文件统计
- 成功后 toast 含 "Open PR" 链接
- "Commit and create PR"：commit → push → `gh pr create --fill`
- 已有 PR 或在主分支时，第三个意图按钮完全隐藏

**技术决策：**

- `GitDialogMode::CreatePr(PrState)` 第三变体
- `CommitIntent::CommitAndCreatePr` 新变体
- 私有 `CommitOutcome` 枚举解耦意图与执行阶段
- `start_confirm` 在单个 `ctx.spawn` 中链式执行三个操作
- `create_pr` 支持 `Option<&str>` 的 title 和 body

**依赖：** APP-3920。完成 Git 操作三部曲。

#### APP-3923: AI-autogenerated Commit Messages and PR Metadata

**目的：** 对话框打开时自动生成草稿 commit message；创建 PR 时自动生成 PR 标题和描述。

**关键行为：**

- **Commit message：** 后台 AI 生成，占位符 "Generating commit message..."，用户已输入则静默丢弃，失败不弹 toast
- **PR title/description：** 并行调用（`futures::try_join!`），AI 失败自动回退 `--fill`
- Diff 输入截断：最大 16,000 字符，非跟踪文件每文件最大 4,000 字节

**技术决策：**

- 新模块 `ai/generate_code_review_content/`
- 单一端点 + `OutputType` 枚举（CommitMessage / PrTitle / PrDescription）
- 无单独 AI 功能开关，由 `GitOperationsInCodeReview` 统一门控
- 隐私/企业用户 guard 标记为后续工作

**依赖：** APP-3922。

#### APP-4125: Unified Git Operations Dropdown

**目的：** 将下拉菜单简化为始终固定三项（Commit / Push-or-Publish / PR），仅通过禁用状态反映分支变化。

**关键行为：**

- 三项固定：Commit / Push(或 Publish) / PR(或 Create PR)
- 移除下拉菜单中的链式操作项（仅保留在 commit 对话框内部）
- Push vs Publish 标签和图标根据 `has_upstream` 切换
- Commit 对话框确认按钮改为静态 "Confirm"

**依赖：** APP-3922。

**目的：** 将 "diff against" 控件从原生下拉菜单重新设计为可搜索的浮动选择器。

**关键行为：**

- 按钮样式触发器 + 浮动选择器
- 搜索输入框 + 可滚动目标列表 + 模糊匹配 + 匹配字符加粗

#### APP-4218: Git Operations Dialogs Compare Against Branch's Actual Parent

**目的：** 修复 Push/Publish 和 Create PR 对话框在分支从功能分支创建时显示错误范围。

**关键行为：**

- 父分支 = 距离 HEAD 最近的祖先分支
- Push/Publish 显示 `<parent>..HEAD` 的提交
- 无有效父分支时回退到主分支

**技术决策：**

- 新增 `detect_fork_point` 函数
- 算法：`git rev-list HEAD --not --exclude=<current> --branches --remotes`
- **当前实现范围有限：** 仅 Push/Publish 对话框，PR 侧为后续工作

**依赖：** APP-3920 + APP-3922。

## 三、架构分析

### 3.1 架构模式：TEA (The Elm Architecture) 变体

```
Action (用户交互)
    ↓
Update (handle_action → 修改 Model 状态 + emit Event)
    ↓
Event (跨 Entity 通信)
    ↓
View (render → 声明式 Element 树)
```

每个核心组件都是独立的 **Entity**（`DiffStateModel`、`ReviewCommentBatch`、`GitDialog`），通过事件系统松耦合通信。

## 四、核心数据流

### 4.1 Diff 计算管线

```
[文件系统变更]
    ↓ (watcher + 5s 节流)
GitStatusUpdateModel (单例缓存)
    ↓
DiffStateModel.repository_changed()
    ├── Head:        git diff HEAD (per-file)
    ├── MainBranch:  git merge-base → diff base..HEAD
    └── OtherBranch: git fetch → diff base..HEAD
    ↓
InternalDiffState::Loaded(GitDiffData)
    ↓ (emit NewDiffsComputed)
CodeReviewView.handle_diff_state_model_event()
    ├── invalidate_all() → 全量替换
    └── invalidate_files() → 增量更新 (FileInvalidationQueue)
        ↓
build_view_state_for_file_diffs()
    ↓
convert_hunks_to_diff_deltas() → DiffDelta
    ↓
calculate_hidden_lines() → RangeSet (折叠无关行)
    ↓
render() → viewported_list (虚拟化列表按需渲染)
```

**关键优化：**
- per-file 刷新避免全仓库重算
- 自动检测二进制文件、autogenerated 文件、隐藏 bidi 字符
- 异步 + 中断机制：保存 `SpawnedFutureHandle` 中断上一次计算
- 5 秒节流窗口合并文件系统变更

### 4.2 评论生命周期

```
[创建评论]
    ↓
PendingImportedReviewComment (等待 diff 加载)
    ↓ (diff 就绪后)
flatten + relocate → AttachedReviewComment
    ↓ (UPSERT 语义，按 CommentId 判断更新或插入)
ReviewCommentBatch.comments
    ↓
comment_list_view / comment_rendering (双渲染路径)
    ↓
api::ReviewComment (桥接到 AI API)
```

### 4.3 Git 操作链式执行

```
[用户点击 Confirm]
    ↓
start_confirm (ctx.spawn)
    ├── run_commit()
    │     ↓ 成功
    ├── run_push() (如果意图是 CommitAndPush 或 CommitAndCreatePr)
    │     ↓ 成功
    └── create_pr() (如果意图是 CommitAndCreatePr)
          ↓
GitDialogEvent::Completed
    ↓
CodeReviewView: close dialog + refresh metadata + refresh PR info
```

### 4.4 AI 内容生成

```
[Commit Dialog 打开]
    ↓ (后台)
get_diff_for_commit_message() → 截断至 16,000 字符
    ↓
GenerateCodeReviewContentRequest { CommitMessage, diff, branch }
    ↓ (异步)
成功 + 编辑器为空 → 自动填入
成功 + 编辑器有内容 → 静默丢弃
失败 → 占位符切换为 "Type a commit message"

[PR Create 确认]
    ↓ (并行)
futures::try_join!(
    generate(PrTitle, diff),
    generate(PrDescription, diff)
)
    ↓
成功 → gh pr create --title <ai> --body <ai>
失败 → gh pr create --fill (回退)
```

## 六、设计亮点

### 6.1 增量刷新机制

`InvalidationBehavior` 区分全量刷新和按文件刷新：

```rust
enum InvalidationBehavior {
    All,                    // 全量重载
    AllLockedIndex,         // git index.lock 特殊场景
    Files(Vec<PathBuf>),    // 按文件增量刷新
}
```

配合 `FileInvalidationQueue` 异步任务队列，避免每次文件变更都全量重算。

### 6.2 GitDialog 统一架构

三种 Git 操作共享同一视图壳（标题、按钮、加载生命周期），每个模式通过子模块管理自己的状态和渲染：

```
GitDialog (mod.rs: 共享 chrome)
    ├── commit.rs → CommitState + render_commit()
    ├── push.rs   → PushState + render_push()
    └── pr.rs     → PrState + render_pr()
```

事件契约统一为 `Completed / Cancelled`，简洁一致。

### 6.3 AI 优雅降级

所有 AI 调用都有回退路径，**永远不会因 AI 失败阻断用户工作流**：
- Commit message 失败 → 占位符切换，不弹 toast
- PR title/description 失败 → 自动回退 `gh pr create --fill`

### 6.4 Diff 大小分级

```rust
enum DiffSize {
    Normal,         // 正常渲染
    Large,          // 默认折叠
    Unrenderable,   // 显示 "diff 太大" 提示
}
```

### 6.5 滚动位置保持

`RelocatableScrollContext` 在 diff 内容变更时保持滚动位置，通过 `StableEditorLine` 锚点跟踪行号变化。

### 6.6 观察者模式解耦

`DiffStateModelRepositorySubscriber` 监听仓库变更，通过 `async_channel` 异步传递 `RepositoryUpdate`，解耦文件系统监控与 diff 计算。
